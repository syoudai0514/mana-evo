# バランス初期値・調整運用（履歴＋運用方針）

更新日: 2026-08-25

> **現行数値の正本ではありません。** 数値が競合する場合は `design/12-detailed-balance-design-for-sol-review.md`、`design/20-world-map-evolution-progression.md`、および現行runtimeを優先します。この文書は調整プロセス・受入思想を残す履歴資料です。

この文書は `design/06-battle-and-progression-design.md` の数値運用を補足する正本である。

## 1. 原則

- 初期実装値を空欄にしない。PR #15 では必ず遊べる値を投入する。
- 本番中に、子ども1人のプレイに合わせて裏で自動的にXP・技威力・捕獲率・敵倍率を変更しない。
- バランス変更は `BALANCE_VERSION` を持つリリース単位の変更として、シミュレーション・テスト結果を根拠にPRで反映する。
- タイプ相性・編成・育成による有利は自動調整で相殺しない。
- 数値調整は「238体を個別に場当たり修正」せず、まず共通式→カテゴリ→個別値の順で行う。

## 2. 誰が調整するか

### 実装・数値調整担当

ChatGPT側の実装担当が、以下を行う。

1. 自動シミュレーションを実行
2. 受入基準から外れた箇所を特定
3. 共通式またはマスター値を修正
4. 回帰テストを実行
5. PRへ結果を記録

### ユーザー確認が必要な変更

ゲーム思想そのものを変える場合だけ、実装前にユーザーへ確認する。

例:

- 進化までの目標日数を大きく変える
- にじのわ100%成功をやめる
- ギガシンカ/キョダイバーストの基本ルールを変える
- ボスを完全追従へ変える
- タイプ相性を自動補正へ入れる

一方、承認済みの体験目標を守るための数%〜十数%の数値調整は、実装担当がテスト結果を根拠に行う。

## 3. 調整を走らせるトリガー

調整は次のタイミングで必ず実施する。

1. **238体マスター接続完了時**
   - 全種族・全進化・代表Lvで一括シミュレーションする。
2. **技マスターを追加/変更した時**
   - 与ダメージ、ターン数、技選択の偏りを再計算する。
3. **敵/ボスのステージ割当を追加/変更した時**
   - 通常敵の戦力比、ボス初回戦・再戦を再計算する。
4. **捕獲ランクまたは「わ」の性能を変更した時**
   - HP50%時/低HP時の1投成功率と最大3投成功率を再計算する。
5. **PRをmainへ入れる前**
   - balance regression を必須ゲートとして実行する。
6. **iPhone実機プレイで違和感が出た時**
   - 1戦だけの偶然では変更せず、再現・シミュレーション結果と合わせて調整する。

初期版ではプレイヤー行動の自動収集テレメトリを前提にしない。実機フィードバックとQA結果を根拠にする。

## 4. XP曲線 初期実装

PR #15 の初期値は、現行engineの以下を基準値として使用する。

```text
totalXp(L) = round(6 * (L - 1)^1.9)
xpToNext(L) = totalXp(L+1) - totalXp(L)
Lv上限 = 100
```

238体の進化Lvを投入した後、標準プレイ時の「進化までの日数」を全系列で算出してから、必要なら**個別モンスターではなくXP共通式を先に調整**する。

### 目標

- 最初の相棒: 初回進化 2〜4日 / 最終進化 10〜14日
- 一般3段階: 初回進化 3〜7日 / 最終進化 14〜28日
- レア3段階: 初回進化 7〜14日 / 最終進化 21〜40日
- 追加学習した日は上記より早まってよい

### 調整トリガー

代表的な標準プレイをシミュレーションし、系列の想定進化日数が目標レンジから**20%以上外れる**場合に調整対象とする。

優先順位:

1. 1日あたりの標準獲得XP設定の誤り/重複を修正
2. XP共通式の係数・傾きを調整
3. 進化Lvの系列設計を確認
4. 最後に個別例外

## 5. 技威力 初期実装

初期版は、命中率・PP・反動のような複雑なデメリットをまだ主軸にしないため、通常技の威力を狭い帯域に置く。

```text
基本技       35
標準技       40〜45
中威力技     50〜55
強技/主力技  58〜65
```

現行縦切りの 35〜60 はこの帯域内なので、そのままv1基準として利用できる。

### 調整トリガー

- 同等戦力・等倍・満タンHPの通常敵を通常技1発で倒すケースが頻発する
- `normal` 戦が3〜5ターンから大きく外れる
- `strong` 戦が4〜6ターンから大きく外れる
- 同じ役割の技で、1つだけが常に最適になり他技を選ぶ意味がなくなる

まず威力カテゴリを調整し、それでも外れる技だけ個別調整する。

## 6. 捕獲率 初期実装

初期版は現行engineの式を正とする。

```text
missingHpRatio = 1 - currentHp / maxHp
baseChance = clamp(0.12,
  0.34 + missingHpRatio * 0.62 - catchRank * 0.07,
  0.90)

ほしのわ = ×1.00
ぎんのわ = ×1.20
きんのわ = ×1.50
にじのわ = 100%確定
非にじ上限 = 92%
```

HP50%時の「ほしのわ」目安:

- catchRank 1: 約58% / 1投、最大3投の単純累積で約93%
- catchRank 2: 約51% / 1投、最大3投で約88%
- catchRank 3: 約44% / 1投、最大3投で約82%

※実戦では捕獲失敗後に敵ターンがあるため、3回すべて投げられるとは限らない。

### 調整トリガー

- 普通ランクが `ほしのわ` でも頻繁に3投失敗し、ゲットの楽しさよりストレスが勝る
- レアランクが `ほしのわ` で簡単すぎて上位の「わ」を選ぶ意味がなくなる
- `ぎん` と `きん` の体感差が小さい
- にじのわが100%でなくなるのは仕様違反として即修正

## 7. 通常敵・ボス倍率 初期実装

現行 `src/game/balance.js` は `BALANCE_VERSION=4`。ゾーンLv帯クランプと再戦成長実感を含む。

### 通常敵

| 区分 | referencePower比 |
|---|---:|
| weak | 0.82 |
| normal | 0.92 |
| strong | 1.02 |
| rare | 1.065 |
| elite | 1.12 |

目標ターン数:

- weak: 2〜4
- normal: 3〜5
- strong: 4〜6
- rare: 4〜7
- elite: 5〜8

### ボス

| Rank | 目標戦力 | HP | 攻撃 | 防御 |
|---|---:|---:|---:|---:|
| C | ×1.02 | ×1.20 | ×1.02 | ×1.00 |
| B | ×1.08 | ×1.35 | ×1.04 | ×1.03 |
| A | ×1.14 | ×1.50 | ×1.07 | ×1.05 |
| S | ×1.20 | ×1.65 | ×1.10 | ×1.08 |
| EX | ×1.28 | ×1.80 | ×1.12 | ×1.10 |

ボスは初回挑戦時にsnapshotを固定するため、調整後も既存snapshotを勝手に強化しない。

### 調整トリガー

- 通常敵が上記ターン数から継続的に外れる
- 同等戦力・等倍の通常敵から満タン一撃KOが頻発する
- ボスが初見で通常敵とほぼ同じ短さになる
- ボスが攻撃力過多で、工夫する前に一撃で壊滅する
- ボスがHP過多で、勝敗が決まっているのに長時間削るだけになる
- ボスsnapshot後にプレイヤー戦力が+20%成長しても「明確に楽」にならない

ボスが弱い場合は、原則として攻撃力を先に上げずHP/防御/行動設計を先に見る。ボスが理不尽な場合は攻撃倍率を先に下げる。

## 8. 調整の優先順位

異常を見つけたら、以下の順で直す。

1. バグ・二重加算・式の誤り
2. 全体共通式
3. 難易度カテゴリ/ロール
4. 特定系列
5. 個別キャラ/個別技

238体を個別パッチの集合にしない。

## 9. PR受入条件

main merge前に最低限、以下を自動検証する。

- Lv1 / 5 / 10 / 20 / 30 / 50 / 100 × 全238体の能力値生成
- 全進化で能力値非減少
- 全通常敵区分の実戦力比
- 代表対戦のターン数
- 等倍通常敵の異常な一撃KO検出
- 各catchRank × HP50%/25%/1HP × 各「わ」の成功率
- ボス初回snapshot固定
- +10/+20/+35/+50%育成後の通常再戦が段階的に有利になること
- チャレンジ再戦のみ現在戦力へ再スケール

このゲートを通した結果をPRへ記録してからmainへ入れる。
