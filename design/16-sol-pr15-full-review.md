## P0

### P0-1. `catchRank` の正本規則と238体CSV実値が一致していない

`design/11` / `design/12` は次の規則を正式候補としている。

- common第1形態=1 / rare=2 / epic=3 / legend=4
- 中間形態 = **同系列第1形態 +1**
- 最終形態 = **同系列第1形態 +2**
- 上限5

しかし13系CSVは、実質的に **各形態自身の `catchRarity` のrank + (stage-1)** で生成されている。

例:

- F004: No.010 common rank1 → No.011 common rank2 → No.012 rare **rank4**。正本文言どおりなら最終はrank3。
- F022: No.064 common rank1 → No.065 rare **rank3** → No.066 epic **rank5**。正本文言どおりなら中間rank2 / 最終rank3。

これは単発誤記ではなく、進化途中で `catchRarity` が変わる系列に系統的に発生する。中間形態は `wildCatchable=True` もあるため、単なる監査列の問題ではなく実際の捕獲率へ影響する。

**修正方針:** 現在の優先順位では `design/12` がCSVより上位なので、まず「同系列第1形態基準」を正とし13系CSVを再生成する。もし各形態自身のrarityを使う意図へ変更するなら、設計書を先に明示変更し、その後CSV・validatorを同期する。どちらにしても `catchRank` validatorを追加する。

### P0-2. `held_item_levelup` の固定Lv条件が正本間で矛盾

`design/11` は「指定アイテム装備 + 必要Lv以上になるLvUP」と書く一方、最新の `design/12` と14系CSVは **固定Lv条件なし。指定アイテム装備後の次の実LvUPでReady** としている。

対象11遷移:

- 058→059 `emberwick`
- 062→063 `sunscale`
- 068→069 `steelplate`
- 092→093 `windband`
- 123→124 `frostgem`
- 141→142 `barkarmor`
- 149→150 `nightfeather`
- 155→156 `steelplate`
- 173→174 `skyplume`
- 185→186 `dragonfang`
- 197→198 `corepart`

**修正方針:** 優先順位どおり最新 `design/12` を採用し、「固定Lv条件なし」に統一する。`design/11` の必要Lv表記を撤去し、QAも「装備→実LvUP→Ready」を検証する。

## P1

### P1-1. stone / held-item進化の体験日数を検証できる「アイテム最速入手時点」がない

level進化はXP曲線から日数を評価できるが、stone21件 / held-item11件はアイテムがいつ手に入るかで進化速度が決まる。特に held-item は固定Lv条件をなくすため、アイテムが早期入手できると次のLvUPで即進化できる。

**必須:** 進化アイテムごとに `unlockMilestone` または `earliestAcquisition` を正本化し、「最短取得でも想定進化体験を壊さない」validatorを追加する。レベル条件を勝手に足して解決しない。

### P1-2. 通常敵の完全追従ソフトスケールは「Lvを上げた成長感」を打ち消す

`design/06` は「育てた結果として過去の敵を圧倒できる」とする。一方、最新設計では通常敵が毎回現在手持ち平均へ追従するため、**Lv上昇そのもののメリットは通常戦の相対難度からほぼ消える**。技・タイプ・特殊形態は追従対象外なので一部の成長感は残るが、学習→XP→LvUPの主報酬が戦闘時間へ反映されにくい。

これは学習ゲームでは重要。努力の直後に可視的な改善が出ないと「勉強して育てた」因果が弱くなる。

**必須受入条件:** 同じ既クリア通常敵に対し、初回時点からプレイヤー戦力が+20%程度伸びた場合、平均決着ターンが少なくとも1ターン短くなる仕組み/上限/再戦ルールを設計する。現在エリアで低Lv新規キャラを育てやすい目的は維持する。具体アルゴリズムはsimulationで決めるが、「常に100%追従」は不可。

### P1-3. 40/60/80/100の技帯域だけでは技選択が形骸化しうる

同タイプ・同追加効果なら期待威力は概ね:

- 威力40 / 命中100% = 40
- 威力60 / 命中100% = 60
- 威力80 / 命中95% = 76
- 威力100 / 命中90% = 90
- burst110 / 命中95% = 104.5

コスト・PP・反動・状態異常がないため、同じ相性なら100技が80/60を支配する。

**必須:** formal move masterで「4技中最低2つは、代表的な相性/用途のどこかで非劣位になる」受入条件を置く。タイプcoverage、`まもる`、明確な用途差で選択理由を作る。単に4つ並べるだけにしない。

### P1-4. healer由来キャラの一部は説明文と `hpTank` の体験が一致しない

8ロールへの変換自体は、未実装のhealer/supportへBSTを浪費しないという意味で妥当。ただし次は説明文から回復・支援を強く期待させる。

**強い不整合:** No.041 / 050 / 098 / 209 / 210 / 235

- No.041: においで「なかまは げんきに」
- No.050: 「あたると きずが なおる」
- No.098: 「ねている あいだに きずが なおる」
- No.209: 「きずを なおす」
- No.210: 「いのちを もどす」
- No.235: 「はっぱ いちまいで もりが よみがえる」

**identity watch:** No.042 / 049 / 051 / 099 / 115 / 116 / 175 / 176 / 177 / 208

また No.181 / 182 は「相手の技を覚える/つなげる」という設定なので、全員共通の威力profileだけでは個性が出ない。

**修正方針:** base statsを今すぐ変更する必要はない。`combatRoleV2=hpTank/balanced` は初期数値として維持しつつ、formal move masterで上記個体の設定を表現できるかを必須レビュー項目にする。設定文を数値都合で書き換えない。

## XP

`totalXp(L)=round(6*(L-1)^1.9)` と通常3戦normal中心=約330XP/日は良い。

330XP/日の目安:

- Lv17: 1,164XP ≒ 3.5日
- Lv19: 1,456XP ≒ 4.4日
- Lv33: 4,344XP ≒ 13.2日
- Lv38: 5,724XP ≒ 17.3日
- Lv43: 7,283XP ≒ 22.1日
- Lv48: 9,019XP ≒ 27.3日
- Lv55: 11,741XP ≒ 35.6日

追加学習で早まる余地もあり、学習報酬として分かりやすい。

## 技

STAB1.20、急所なし、ダメージ乱数なしは初期版として妥当。結果予測がしやすく、幼い子でも「なぜ勝った/負けた」を理解しやすい。

ただし技威力帯域だけでは高威力技が支配するのでP1-3を追加する。

## 通常敵

BOX最強個体を参照せず、現在手持ちだけで育成敵を作る方向は良い。新規捕獲キャラの育成コストを下げる。

一方、100%追従するとLvUP報酬の体感が消えるためP1-2を必須修正。

## ボス

`teamWeighted 50/30/20`、`rosterWeighted ×0.85`、`carryFloor=最強×0.80` のmaxは妥当。Lv80+低Lv2体や弱い編成への付替えだけで初見ボスを極端に弱くする抜け道をかなり抑えられる。

初回snapshot固定→通常再戦固定→challengeだけ再スケールも良い。敗北後の学習/育成が確実に報われる。

## 捕獲

HP50%時のrank5で、3投すべて使う場合の概算成功率:

- ほし: 30%/投 → 約65.7%
- ぎん: 36%/投 → 約73.8%
- きん: 45%/投 → 約83.4%

rank1のきんは87%/投、3投で約99.8%。低rankは捕まえやすく、高rankは良い「わ」の価値が残るため大枠は妥当。

ただしcatchRankの生成規則自体はP0-1を先に直す。

# R1〜R5への回答

## R1. `powerTierV1 = source catchRarity` を初期seedにしてよいか

**YES。初期seedとして開始してよい。現時点で個別No.の強制補正はしない。**

理由: `catchRarity` と `powerTierV1` は列として既に分離されており、まず元資料の意図を保った再現可能な初期値にする方が安全。ここでレビュー担当が印象だけで個別強化/弱体化すると再現性が落ちる。

監視のみ: No.018 / 021（低め）、No.235〜237（高め）。simulationで明確な問題が出た場合だけ `powerTier` を独立変更する。

## R2. 手持ち最大3体へ全員100% Battle XP

**YES。採用。**

BOXには入らず、戦闘開始時メンバーだけ、瀕死でも対象、捕獲したばかりの敵は対象外でよい。

3分割にすると「好きな3体を連れていくほど1体の成長が遅い」という罰が発生する。100%配布はチーム入替え・新キャラ試用の心理的コストを下げる。XP曲線も330XP/日基準なら過剰ではない。

## R3. 共通 `まもる`

**YES。採用。**

- 成功100%
- その敵行動のダメージ/状態を防ぐ
- 次ターン連続使用不可
- 攻撃と同じ1行動を消費
- 予告大技へ確実に機能する

運で避けるのではなく「予告を見て対応したから防げた」という因果が子どもに分かりやすい。ボス大技の威力を高くしても理不尽感を抑えられる。

## R4. healer/support→hpTank/balanced変換

**全件OKではない。統計変換は維持してよいが、個別identity対応が必要。**

強い不整合: 041 / 050 / 098 / 209 / 210 / 235。

ただし初期版へhealer/supportロールを復活させることは推奨しない。formal move master側で設定を表現できるかを必須化し、base statsは現状維持でよい。

## R5. `にじのわ` 供給

**YES。候補仕様を採用。**

- 各学年初回クリア +1
- 全エリア後EX初回 +1
- ランダムなし
- 章末定期配布なし

小1〜小6の6学年運用なら計7個。238体に対して約2.9%しかなく、100%捕獲アイテムとして希少性を保てる。確定報酬にすることで「頑張ったのに出なかった」というランダム失望も避けられる。

「学年」に年長等を含める場合は総供給数だけ再計算し、100%捕獲が日常化しないことを確認する。
