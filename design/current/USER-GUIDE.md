# ManaEvo わたし向け設計書 — CURRENT

更新日: 2026-08-31  
今回の変更: **図鑑画像をまとめて保存し、詳細を連続で見られるようにする**  
正式判断: D-020

この資料は、専門設計書を読まなくても「ManaEvoがどう動くことになっているか」を確認するための保護者・オーナー向け説明です。専門CURRENTと意味が違った場合は専門CURRENTを直すだけでなく、この資料も同じ変更で直します。

---

# 今回なぜ変えるのか

238体の正式画像は揃いましたが、図鑑ではまだ次の不便があります。

- 画像が出るまで灰色に見えることがある
- 一度見た画像でも待っているように感じる
- 詳細から次のキャラへ進めない
- 詳細から一覧へ戻ると一番上に戻る
- 238体を一度端末へ保存して通信待ちを減らす機能がない

今回の設計は「238枚全部を一気に画面へ出す」のではありません。

**ファイルは全部保存できる / 画面用メモリには近くの画像だけ出す**

という方式にします。これがiPhoneで軽く動かすための基本です。

---

# 1. 「モンスター画像を全部保存」ができる

保護者・端末設定に、

**モンスター画像を全部保存**

を追加します。

対象は正式採用されたNo.001〜238だけです。No.239は入りません。

表示例:

- `0 / 238`
- `85 / 238`
- `238 / 238 保存済み`
- `不足あり`
- `更新あり`

途中で通信が切れても、確認済みの画像を最初から取り直しません。不足分だけ再開します。

将来1体だけ画像を直した場合は、原則その1体だけ更新します。7体変わったなら7体だけです。

---

# 2. 「238/238」は数字だけで信用しない

古い画像がHTTPでは正常に返ってくる場合があります。そのため「通信成功したから保存済み」にはしません。

各画像にはSHA-256という実データの指紋があります。

完了扱いになる順番は必ず、

**画像取得 → 実データのSHA確認 → 正式SHAと一致 → 専用キャッシュへ保存成功 → その後だけ1件完了**

です。

そのため、

- 古い画像
- 壊れた画像
- 保存に失敗した画像
- 数字だけ「238」と残っている状態

を238/238とは扱いません。

逆に、画像保存そのものは成功した直後にアプリが終了しても、再開時に実際の保存済みキーを見て「ここまでは終わっている」と復元します。

---

# 3. アプリ更新だけで238枚を消さない

アプリ本体とモンスター画像の保存場所を分けます。

- アプリ本体用キャッシュ: `manaevo-shell-vN`
- 正式モンスター画像用: `manaevo-dex-art-v1`

アプリ本体が更新されたという理由だけで、保存済み238枚を全部削除しません。

また、正式画像をService Worker用と図鑑用に二重保存する方式にもせず、正式画像の保存担当を1つにします。

---

# 4. 保存済み画像を見るたびに238件チェックしない

画像を1枚表示するたびに、

- 画像一覧をネットから取り直す
- 保存済み238件を全部走査する

という処理は禁止します。

通常は、現在の画像の版をメモリ上の一覧から確認し、端末キャッシュにあればそこからすぐ返します。

238件の確認や古い画像整理は、「更新する」「不足分を修復」などのまとまったタイミングだけで行います。

---

# 5. 全部保存しても238枚全部をメモリへ出さない

画像ファイルを端末に置くことと、画像を表示用メモリへ展開することは別です。

238枚全部を同時に展開すると、iPhoneのメモリを圧迫して逆にスクロールが重くなる可能性があります。

そのため、

- 画像ファイル: 238体すべて保存可能
- 図鑑一覧: 今見えている範囲＋2〜3画面先くらいだけ準備
- 詳細: 今のキャラ＋前後2体程度を先回り

にします。

ブラウザの`lazy loading`任せだけにはせず、ManaEvo側でも準備する範囲を制御します。

---

# 6. 詳細画面から前後へ進める

詳細画面には常に、

**← まえ　｜　ずかんへ　｜　つぎ →**

を表示します。

例えばNo.100を開いたら、そのままNo.101、No.102へ進めます。

「ほのお」で絞り込んでいたら、その絞り込み結果の中だけで前後へ進みます。突然別タイプへ飛ばしません。

一覧の先頭/最後では前/次を無効にします。

---

# 7. 「ずかんへ」で元いた場所へ戻る

例えばNo.100付近までスクロールし、検索や絞り込みをしてNo.103を開いた場合、一覧へ戻るときは、

- 検索文字
- エリア
- タイプ
- 絞り込みパネル状態
- どの検索結果を見ていたか
- どのキャラ付近にいたか
- そのキャラが画面のどの高さにいたか

を戻します。

単純なスクロール距離だけを覚えるのではなく、**基準のキャラ＋その画面位置**で戻します。画像読み込みで少し高さが変わっても位置がずれにくくするためです。

---

# 8. Safari/PWAの戻る履歴も壊さない

今回のレビューで特に厳しく確認した部分です。

一覧から詳細を開くと、Safari履歴を1つ追加します。

詳細で「次へ」「前へ」を押しても、キャラごとに履歴を増やしません。同じ詳細履歴を書き換えます。

通常の一覧起点で「ずかんへ」を押した場合は、画面だけ一覧へ切り替えません。

**ずかんへ → Safari履歴を1つ戻す → 戻るイベントで一覧を復元**

という順番にします。

これにより、

`一覧 → A → 次へB → ずかんへ → 一覧 → C → Safari戻る1回`

の結果は必ず**一覧**になります。昔閉じたBへ戻ったら不具合です。

Capture/Evolutionなどから直接詳細へ入っていて、直前に図鑑一覧履歴がない場合は、無関係なSafari履歴を戻りません。現在の詳細履歴を図鑑一覧履歴へ置き換えてから一覧へ戻します。

---

# 9. iPhoneで保存データが消える可能性も考える

Webアプリの保存領域は、iPhoneの空き容量不足などでOSに削除される可能性があります。

そのため「一度保存したら永久に絶対消えません」とは言いません。

代わりに、

- 1枚消えた → 237/238、`不足あり`
- 全部消えた → 0/238
- 表示上238でも実物が1枚ない → 237/238へ訂正
- 表示情報だけ消えて実物238枚が残る → 実物を確認して238/238へ復元

とします。

容量表示は参考値です。実際に保存できなかった場合を最終判定にします。

---

# 10. リリース前は本当に238体全部で確認する

今回は「全238体を保存してオフラインでも見られる」と言う機能なので、一部サンプルだけでは合格にしません。

必須確認:

- ネット完全OFFでNo.001〜238全部を表示
- 001→238→001まで詳細連続閲覧
- 長時間見ても訪問数に比例してメモリが増え続けない
- 1体変更なら画像通信1件だけ
- 7体変更なら7件だけ
- ダウンロード途中で終了しても保存済みを無駄に取り直さない
- 古い画像が200で返ってもSHAが違えば完了扱いしない
- 1枚削除/全削除/表示情報だけ不整合の各ケースを正しく修復
- 普通に図鑑を開いただけで238件一斉通信しない
- 保存済み画像1枚ごとにmanifest通信や238件全走査をしない
- `ずかんへ` とSafari戻るの両方で元の一覧位置へ戻る
- 閉じた詳細がSafari履歴に残って後から復活しない

---

# 11. 変更してはいけないもの

今回の変更は図鑑の画像表示・保存・閲覧導線です。

次は変えません。

- モンスターNo./名前/属性/進化などのゲームデータ
- FORMAL承認済みという意味
- No.239除外
- 学習/バトル/捕獲ルール
- クラウドの子ども進捗データ

図鑑の閲覧履歴やスクロール位置は同じSafari/PWAセッション内で使うだけで、家族クラウドセーブには入れません。

---

# 12. 完成したときの理想

一度「モンスター画像を全部保存」する。

**図鑑を開く → 画像がすぐ見える → 詳細を開く → 次へで次々確認 → ずかんへ/Safari戻る → 元の絞り込み・元の位置へ戻る。**

通信が弱い場所でも238体を確認でき、長く見てもiPhoneがだんだん重くならない。

これが今回の完成条件です。
