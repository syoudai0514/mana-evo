# ManaEvo — オーナー向け わかりやすい設計書

更新日: 2026-08-29
状態: CURRENT USER-FACING COMPANION
対象読者: IT・ゲーム設計の専門知識を前提としないManaEvoオーナー

## この資料の目的

専門家・AI向けの設計書とは別に、「ManaEvoが今どういうゲームなのか」「なぜそのルールなのか」「変更すると何が変わるのか」を専門用語をできるだけ使わず説明するための資料です。

この資料は `design/current/**` の代わりではありません。正確な実装契約は専門設計書を正本とし、この資料はその内容をオーナーが理解・判断できる言葉へ翻訳したCURRENT companionです。

## 恒久運用ルール

1. ManaEvoの設計を変更する場合、専門設計書だけを更新して完了してはいけません。
2. 同じproduct-changeで、この資料の該当箇所も更新します。
3. 変更時には、オーナーへ「今までどうだったか / 何を変えたか / なぜ変えたか / 子どもの体験がどう変わるか / 注意点」を分かりやすく表示します。
4. 内部ID、DB、関数名などを理解しないと判断できない説明は禁止します。必要な専門用語には日本語の意味を併記します。
5. 専門設計書と本資料が食い違った場合は専門設計書を正として、同じ変更セット内で本資料のdriftを修正します。
6. 初回の全体版は再建の最終release時までに完成させます。それまでも新しい設計変更が発生した領域は、その都度この資料へ反映します。
7. release後も恒久的に最新化します。

## 変更説明の標準フォーマット

設計変更をオーナーへ報告するときは最低限、次の5点を示します。

- **これまで:** 変更前はどういうルールだったか
- **変更後:** 新しいルールは何か
- **理由:** なぜ変更するのか
- **子どもへの影響:** 実際の遊び・学びがどう変わるか
- **守ること:** 悪用防止、公平性、データ保持など重要な安全条件

## 最新の設計変更: 学習とバトルチケット

### これまで

追加学習で正解した回数をもとにバトルチケットを増やす仕組みはありましたが、「簡単な同じ問題だけを大量に解く」「無料練習までカウントされる」など、学習よりゲームを効率よく進める攻略法が生まれる余地がありました。

### 変更後

毎日の基本学習を終えたあと、意味のある追加学習で **5問正解するとバトルチケットを1枚**もらう方式にします。

ただし、同じ種類の知識だけで5問を埋めることはできません。1枚のチケットに使える同じ知識の正解は最大3問までです。たとえば「たし算3問 + ひき算2問」はOKです。

忘れかけた頃に出る復習問題や、一度間違えたあと少し時間を空けて自力で解き直した問題も、普通の正解1問として扱います。

一方、答えを見た直後に同じ答えを押すだけの問題、すでに十分できる簡単な問題の不要な繰り返し、無料・おかわり練習、誤答そのものはチケット獲得には数えません。

### 理由

目的は「長時間画面を見た子」や「ゲームの仕組みを攻略した子」を有利にすることではなく、**実際に学習した分だけ自然に遊べる**状態にすることです。

正解までの秒数には条件を付けません。本当に理解していて1〜2秒で解ける子を、わざと待たせることはしません。

### 子どもへの影響

得意な子は速く解いても損をしません。苦手な子も、間違えたこと自体で罰を受けず、その後に自力で思い出せれば正解1問分として回収できます。

同じ簡単な問題だけを連打するより、少し違う知識も学んだ方が自然にチケットへつながります。ただし「算数・国語・英語を必ず混ぜる」といった教科の強制はしません。

### 守ること

- 5問正解 = 1チケット
- 同じ知識は5問中最大3問
- 正解が速いことを罰しない
- 難しい問題だからチケットを増やすこともしない
- 間違いをわざと増やして得する仕組みにしない
- 答えを見ただけではカウントしない
- 無料・おかわり練習からチケットを増やさない
- 端末再読み込みやプロフィール切替で同じ正解を二重カウントしない

## 最新の設計変更: クラウド保存のタイミング

### これまで

学習やゲームの進捗は端末へすぐ保存され、クラウドは最後の変更から約1.4秒後に同期する仕組みでした。オンライン復帰やアプリ画面へ戻った時にも同期していました。

ただし、短い間隔で保存が続くと1.4秒の待ち時間が何度もリセットされるため、クラウドへの到達が想定より遅れる余地がありました。また、プロフィール切替で画面を再読み込みする直前に待機中だった同期が完了しない可能性もありました。

### 変更後

学習・バトル・モンスターなどの進捗は、これまでどおり**まず端末へ即保存**します。その上でクラウドは次のルールで自動同期します。

- 普通の操作では最後の保存から **0.8秒後**を目安にまとめて同期
- 操作が連続していても、最初の未同期保存から **最大4秒**で一度はクラウド同期を試す
- アプリ起動時、通信復帰時、アプリへ戻った時はすぐ同期を試す
- アプリをバックグラウンドへ送る時も同期を試す
- プロフィールを切り替える時は、画面を再読み込みする前に同期を試す
- 通信が切れていて同期できなくても、端末保存は消さず、次に通信が戻った時に再試行する

### 理由

子どもが何問も続けて学習したり、バトルを連続して遊んだ時でも、「端末には残っているがクラウドには長時間届いていない」という時間を短くするためです。

一方で、1問ごと・1タップごとに通信完了を待たせると、操作が遅くなり通信状態にも左右されます。そのため「端末保存は即時」「クラウドは短時間でまとめる」という2段構えにしています。

### 子どもへの影響

通常は保存待ち画面を見せません。学習やバトルはそのまま続けられます。

端末を急に閉じたり通信が切れたりしても、まず端末には保存されています。次回起動や通信復帰時にクラウドへ追いつかせます。

### 守ること

- クラウド通信失敗で端末内の正常な進捗を消さない
- 連続操作で同期を無期限に先送りしない
- 同じプロフィールを2台で別々に進めた場合は勝手に後勝ち上書きしない
- 別プロフィール同士なら安全に統合できる現在の仕組みを維持する
- TESTモードのデータは通常クラウドへ送らない
- 子どもの通常操作をクラウド通信待ちで止めない

## クラウドと端末の内容が違うとき、どうするか

ここが一番大事な部分です。ManaEvoは単純に「新しそうな方で上書き」はしません。

| 状況 | ManaEvoの動き | どう考えればよいか |
|---|---|---|
| この端末だけ進んでいて、クラウドは前回同期のまま | **端末 → クラウドへ保存** | 普通の遊び方。端末で増えた進捗をクラウドへ追いつかせる |
| 別端末で進んでいて、この端末は何も変更していない | **クラウド → この端末へ反映** | iPadで遊んだ続きをiPhoneで開くイメージ |
| 新しい端末・再インストール直後でクラウドに既存データがある | **クラウドを復元** | 空の初期データで家族のセーブを上書きしない |
| 初めてクラウドを使い、端末にだけ既存データがある | **端末データを最初のクラウド保存にする** | 今まで遊んだ内容をそのままクラウド化する |
| iPhoneではパパ、iPadでは子ども、のように別プロフィールがそれぞれ進んだ | **両方を自動で統合** | 人が違うので、両方の進捗を残せる |
| 同じ子どものプロフィールを2台で別々に進めた | **勝手に統合・上書きしない** | どちらを残すべきか機械には判断できないので保護者確認 |
| オフライン中に学習・バトルした | **端末に保存して遊び続ける** | ネットがなくても進捗を止めない |
| オフラインで進めた後、ネットが戻った | **その時点でクラウドと比較して同期** | 端末が必ず勝つのではなく、他端末の変更も確認する |
| アプリを閉じる・バックグラウンドへ送る | **最後に同期を試す** | 間に合わなくても端末保存は残り、次回起動で再試行する |
| プロフィールを切り替える | **今の人のデータを同期してから切替を試す** | パパの途中データを子どものデータへ混ぜない |
| クラウドがエラー・タイムアウト | **端末データを保持して後で再試行** | ネット障害で正常な進捗を消さない |
| 同期中にさらに問題を解いた・ゲームが進んだ | **古い同期完了だけで「全部同期済み」にしない** | 同期中に増えた分も、続けてもう一度クラウドへ送る |
| TESTモードで全開放データを使った | **通常クラウドへは送らない** | 開発用データで家族の本物のセーブを汚さない |

### 具体例1: iPadで子どもが勉強した後、iPhoneで開く

1. iPadで学習 → iPadへ即保存。
2. 約0.8秒〜最大4秒以内を目安にクラウドへ同期。
3. 後でiPhoneを開く。
4. iPhone側に未同期変更がなければ、クラウドの新しい進捗を取得。
5. iPhoneでも続きから遊べます。

### 具体例2: 2台とも同じ子どもでオフライン利用した

これは自動で片方を消してはいけないケースです。

たとえばiPadで算数を10問進め、同じ時間にiPhoneでバトルと捕獲を進めた場合、どちらを単純に「新しい方」と決めると片方を失う可能性があります。同じプロフィールが両方で変わったことを検出したら、**子どものプレイ中は端末データをそのまま守り、保護者画面で確認**します。

### 具体例3: iPhoneはパパ、iPadは子ども

プロフィールが別なら、安全に分けられます。

- iPhoneでパパの進捗が増える
- iPadで子どもの進捗が増える
- クラウド同期時にパパ分と子ども分をそれぞれ残して統合

このとき、学習だけ子ども・モンスターだけパパ、のような混ぜ方は禁止します。**1人分の学習・ゲーム・報酬はセットで扱います。**

### 具体例4: 同期ボタンを押した瞬間にも子どもが遊び続けている

同期開始時点のデータを送っている間に、さらに1問解いたりバトル結果が保存されることがあります。

その場合、最初の通信が成功しても「全部終わり」とは扱わず、**同期開始後に増えた変更が残っていれば続けて再同期**します。古い通信の完了通知で、新しい進捗まで同期済みと誤判定しないことを必須条件にします。

### 保護者に選んでもらうのは最小限

通常は自動で安全に同期します。保護者確認が必要なのは、主に**同じプロフィールを複数端末で別々に進め、どちらも大切な変更を持っている場合**です。

子どもが学習・バトル中に突然「どっちを残しますか？」と聞かれるようにはしません。端末側の進捗を守ったまま、保護者画面で後から解決します。
