# 変更後の使い方

## 1. 238体の画像を「端末にまとめて保存」できる

保護者・端末設定の中に、

**「モンスター画像を全部保存」**

を追加します。

押すと、現在正式採用されているNo.001〜238の画像をまとめて端末側へ保存します。

進み具合は、例えば

- 0 / 238
- 85 / 238
- 238 / 238 保存済み

のように見えるようにします。

途中で通信が切れても、最初からやり直しにはしません。保存できた画像は残して、不足分だけ再開します。

また、将来1体だけ画像を直した場合、238体全部を再ダウンロードするのではなく、**変わった画像だけ更新**する設計です。

## 2. いったん保存した画像は、なるべく通信待ちをしない

画像ファイルを端末に保存することと、238体全部を一度にメモリへ展開することは別にします。

238体を全部メモリへ広げると、かえってiPhoneが重くなる可能性があるためです。

そのため、

- ファイル自体は238体分を端末へ保存できる
- 画面表示は「今見ているキャラ」と「その前後」を優先して準備する

という方式にします。

これなら保存済みの画像を使いつつ、端末のメモリを無駄に使いません。

## 3. 詳細画面から、そのまま前後のキャラへ進める

詳細画面に、常に分かる形で

**← まえ　｜　ずかんへ　｜　つぎ →**

を置きます。

例えばNo.100を見たあと、一覧に戻らずそのままNo.101、No.102と続けて確認できます。

検索やタイプ絞り込みをしていた場合は、その絞り込み結果の中で前後へ進みます。

## 4. 一覧へ戻ると、元いた場所へ戻る

例えばNo.100付近までスクロールしてNo.103を開いた場合、

詳細 → ずかんへ

で戻ったときは、図鑑の一番上ではなく、**No.100付近の元いた位置**へ戻します。

検索語、タイプ、エリアの絞り込みもそのまま残します。

単純に「スクロール位置の数字」だけを覚えるのではなく、どのキャラを基準に見ていたかも覚える方式にします。画像読み込みで画面の高さが少し変わっても、戻る場所がずれにくくなるためです。

## 5. 画像がまだ準備できていない時も「壊れたように見せない」

今のように灰色のまま何も分からない状態にはせず、読み込み中だと分かる表示を入れます。

通信エラーの場合も、ただ消えるのではなく再試行できる状態にします。

# なぜ「238体を最初から全部読み込む」にしないのか

「全部ダウンロード」と「全部同時表示」は別です。

238体分のファイルを端末へ保存するのはよいのですが、238枚を同時に画像として展開すると、iPhoneのメモリを圧迫して逆にスクロールが重くなる可能性があります。

そこで、

**端末には全部保存できる / 画面では近くの画像だけ先回りして準備する**

という方式にします。

この方が「ヌルヌル動く」という目的に合っています。

---

# iPhoneでの注意点

Webアプリの保存領域は、iPhone側の容量不足などでOSに削除される可能性があります。

そのため「一度保存したら永久に絶対消えない」とは表示しません。

代わりにアプリ側で、

- 238 / 238 保存済み
- 不足あり
- 更新あり

を判定し、不足分だけ修復できるようにします。
